## Findings

### SA-2026-10-11-01 · Medium · Containers kept Docker's default capabilities
- **Where:** `deploy/docker-compose.yml`: every service.
- **Evidence:** `docker inspect` showed `CapDrop=[]` and no `no-new-privileges` for all eleven containers. LiveKit runs
  as root (`User=""`) and is reachable from the internet (7881/tcp, 7882/udp, 443/tcp, 3478/udp, 30000–30100/udp).
- **Impact:** if LiveKit (or another service) had a remote-code-execution bug, the attacker would get root inside the
  container with Docker's default capability set (`CAP_NET_RAW`, `CAP_CHOWN`, `CAP_SETUID`, …). That makes escaping
  the container and attacking the compose network easier.
- **Fix:** a shared `x-hardening` block: `cap_drop: [ALL]` and `no-new-privileges:true` on every service except
  cadvisor (privileged, see SA-2026-10-11-07). LiveKit still binds 443, because Docker sets
  `ip_unprivileged_port_start=0` in containers. It still reads its root-owned TLS key, because it is the file's owner.
  Verified after the deploy: zero restarts, no permission errors, and TURN over TLS answers with its certificate.
- **Status:** fixed in PR #31 (`Fix SA-2026-10-11-01`); live (deployed 2026-10-11).

### SA-2026-10-11-02 · Medium · `provision.sh` re-pinned SSH host keys on every run
- **Where:** `scripts/provision.sh` (host-key step).
- **Evidence:** every run overwrote `deploy/ansible/known_hosts` with the result of `ssh-keyscan`, even for an
  existing server (for example after an IP change, or a resize).
- **Impact:** an attacker able to intercept traffic between the operator and the server during a re-run would get
  their key pinned. The next `deploy.sh` would then copy the merged `.env` (tunnel token, LiveKit secret, Cloudflare
  and Hetzner tokens, Grafana password) to them.
- **Fix:** the pin records the Hetzner server id. Later runs check that every key the server presents is already
  pinned, and stop with a warning if not. Only a new server gets a new pin. Tested with a legacy pin, a marked pin,
  an unpinned key against each kind of pin, and a new server id.
- **Status:** fixed in PR #31 (`Fix SA-2026-10-11-02`); it takes effect on the operator's machine with no deploy.

### SA-2026-10-11-03 · Medium · No HSTS on the public host
- **Where:** `deploy/nginx/default.conf`; Cloudflare edge settings.
- **Evidence:** `scripts/security-check.sh https://cipheroom-beta.alexfix.dev` reported no `Strict-Transport-Security`
  header. The Cloudflare dashboard toggle that the `security` skill relies on was off.
- **Impact:** a first visit typed as `http://…` can be downgraded or redirected by a network attacker before Cloudflare's
  HTTPS redirect.
- **Fix:** nginx sends `Strict-Transport-Security: max-age=31536000` (this host only, no `includeSubDomains`), also on
  the `/grafana/` locations that replace the server-level headers. Browsers ignore it over plain HTTP, so LAN access
  at home is unaffected.
- **Status:** fixed in PR #31 (`Fix SA-2026-10-11-03`); live since `sha-5df4490` (`security-check.sh` shows no warnings).

### SA-2026-10-11-04 · Low · Root still has the provisioning SSH key
- **Where:** server: `/root/.ssh/authorized_keys` (1 key, put there by Hetzner at creation).
- **Impact:** none today: `PermitRootLogin no` and `AllowUsers cipheroom`. If sshd's configuration ever regressed,
  the key would allow root login directly.
- **Fix:** an Ansible task in `base` that removes root's `authorized_keys`.
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-04, -09, -10`).

### SA-2026-10-11-05 · Low · One flat Docker network
- **Where:** `deploy/docker-compose.yml`: all services on `cipheroom_default`.
- **Impact:** a compromised internet-facing service (LiveKit, web, cloudflared, api) can reach the unauthenticated
  telemetry endpoints (Loki push, Prometheus, Tempo, the collector) and cadvisor. Exploiting this requires a
  container compromise first.
- **Fix:** separate networks. `default` (edge, with internet) has api, web, livekit and cloudflared. `telemetry`
  (internal) has the observability stack. `otlp` (internal) has only the api and the collector; `grafana`
  (internal) has only web and Grafana.
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-05`).

### SA-2026-10-11-06 · Low · Base images on moving tags; no automated dependency updates
- **Where:** `src/Cipheroom.Api/Dockerfile` (`sdk:10.0`, `aspnet:10.0-noble-chiseled`), `web/Dockerfile`
  (`node:lts-alpine`, `nginx-unprivileged:1.31-alpine`); no `.github/dependabot.yml`. Servers pull by tag, not digest.
- **Impact:** builds aren't reproducible, and a compromised upstream tag would be picked up by the next build.
  Moving tags do bring security patches automatically, which is why this is Low.
- **Fix:** `.github/dependabot.yml`: weekly grouped updates for Actions, Dockerfile bases, compose images, NuGet, npm
  and Terraform, with a 3–7 day cooldown. Dockerfile bases are pinned by digest; `node:lts-alpine` → `node:24-alpine`.
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-06`).

### SA-2026-10-11-07 · Low · cadvisor is privileged and mounts the Docker socket
- **Where:** `deploy/docker-compose.yml` → `cadvisor` (observability profile only).
- **Evidence:** `privileged: true`, plus `/var/run/docker.sock` mounted `:ro`. A read-only mount doesn't restrict
  the Docker API.
- **Impact:** a cadvisor vulnerability means root on the host. It isn't published, and the observability profile
  is optional.
- **Status:** accepted, and mitigated by SA-2026-10-11-05: cadvisor is now reachable only from the internal telemetry
  network. Per-container metrics still need the privileges.

### SA-2026-10-11-08 · Low · `AllowedHosts: *` in production
- **Where:** `src/Cipheroom.Api/appsettings.json`; compose doesn't override it.
- **Impact:** small: the api is only reachable through nginx and the tunnel, and it builds no absolute URLs from
  `Host`. Still, the `security` skill asks for the real hostname.
- **Fix:** compose passes `AllowedHosts` from `API_ALLOWED_HOSTS` (default `*`, so LAN access by IP keeps working
  at home). Ansible sets `PUBLIC_HOST;localhost` on a server. A functional test covers it.
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-08`).

### SA-2026-10-11-09 · Low · sshd offers legacy algorithms
- **Where:** server: `sshd -T` lists NIST ECDH key exchange and `hmac-sha1` / `umac-64` MACs.
- **Impact:** no practical attack today; it's hardening.
- **Fix:** set `KexAlgorithms` / `MACs` in `deploy/ansible/roles/base/templates/sshd.conf.j2` (keep
  `mlkem768x25519-sha256`, `sntrup761x25519-sha512`, `curve25519-sha256`; ETM SHA-2 MACs).
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-04, -09, -10`).

### SA-2026-10-11-10 · Low · `net.ipv4.conf.all.send_redirects = 1`
- **Where:** server sysctl (forwarding is on for Docker).
- **Fix:** set `send_redirects=0` in `/etc/sysctl.d/90-cipheroom.conf`, which `base` already manages.
- **Status:** fixed in the follow-up PR (`Fix SA-2026-10-11-04, -09, -10`).

### SA-2026-10-11-11 · Info · ufw shows only SSH, but Docker-published ports bypass it
- By design, and documented in the `base` role: Docker's iptables rules come before ufw's. The Hetzner firewall
  (Terraform) is the effective filter, and the outside scan matched it exactly. **Accepted.**

### SA-2026-10-11-12 · Info · Admin user has passwordless sudo
- Login is by key only, for a single operator with a dedicated key. A sudo password would add little and would
  break unattended Ansible runs. **Accepted.**

### SA-2026-10-11-13 · Info · 101 `docker-proxy` processes for the TURN relay range
- One per published UDP port (30000–30100). This costs a little memory and is not a security issue. `"userland-proxy": false` in
  `daemon.json` would remove them. **Accepted** (noted for performance).

## Checked and passed
**A. E2EE invariant**
- Private keys are non-extractable at rest. The exportable PKCS#8 copy exists only between creation and the
  one-time backup, and is then wiped (`device-key.ts`, `host-key.ts`).
- `?e2ee=passthrough` only stops *this* browser decrypting what it receives; outgoing frames are always encrypted
  (`frame-cryptor.ts`).
- No hub DTO, log template or telemetry tag carries keys, names, SDP or plaintext. Room ids are logged pseudonymously.
- The LiveKit relay copies signaling untouched and never logs it. LiveKit's token grants join, publish, subscribe
  and data in one room only; participants can't update their own metadata.

**B. Backend**
- All 30 hub commands and queries have FluentValidation validators. Every handler resolves the caller from
  `ConnectionId` to their room (`MediaSessions.*`); relays and data channels are keyed by connection.
- `OpenMediaRelay`: path allowlisted (`/rtc`, `/rtc/v1`), query reduced to an allowlist, the browser's token dropped
  and the server's own token added, at most two relays per connection. A removed participant's relays close and
  LiveKit drops them; they can't open new ones.
- `HubExceptionFilter`: constant messages only. 64 KB receive limit, per-connection token buckets (separate one for
  relay traffic).
- Forwarded headers trusted only from the compose network, and the chain is walked correctly. The client IP is used
  for nothing.
- `HttpClient` and Polly logging stay at Warning (URLs carry Cloudflare ids).

**C. Frontend**
- No `innerHTML`, `bypassSecurityTrust*`, `eval` or `new Function`. No third-party origins.
- `localStorage` holds only UI settings and the user's own display name. `console.*` calls log only error messages,
  never keys.
- CSP `script-src 'self'`, `connect-src 'self'`, `frame-ancestors 'none'`. Live headers verified.

**D. Supply chain**
- Secret scan clean; `deploy/.env` and `deploy/.env.hetzner` are gitignored with mode 600; state, tfvars and
  inventory are gitignored.
- NuGet: no vulnerable packages, including transitive ones. npm: 0 vulnerabilities (all dependencies).
- `images.yml`: actions pinned to commit SHAs, `permissions: contents: read` (`packages: write` only on the job),
  `persist-credentials: false`, no `pull_request_target`.
- `.terraform.lock.hcl` is committed; Ansible collections are pinned to exact versions (this change).

**E. Deploy configuration**
- nginx: headers at server level, `/grafana/api/health` blocked, Grafana login rate-limited; Grafana hardening
  verified live (API needs login, no `/metrics`, login rate-limited).
- Only `web` is published, on `127.0.0.1`. LiveKit's signaling/API port 7880 isn't published.
- LiveKit's embedded TURN (v1.13.9) doesn't relay to restricted/private peer ranges by default (since v1.12.0), so
  TURN can't be used to reach the compose network.
- Terraform: SSH only from the operator's CIDR (validation rejects `0.0.0.0/0`), token only through `HCLOUD_TOKEN`.
- Ansible: `no_log` on every task that handles the env or tokens; `.env` 600 root; DNS token 600 in a 700 directory.

**F. Live server**
- Ubuntu 26.04.1 LTS, 0 pending upgrades, no pending reboot; unattended-upgrades on, with a 04:30 UTC reboot window.
- `sshd -T`: root login, passwords and keyboard-interactive off; `AllowUsers cipheroom`; `MaxAuthTries 3`;
  forwarding off.
- One login user; nobody in the `docker` group; one authorised key for the admin.
- fail2ban `sshd` jail active. ufw: default deny inbound.
- Listening sockets match intent: sshd, LiveKit's published ports, `127.0.0.1:8080` (web), local DNS.
- Docker daemon log rotation (10 MB × 3); socket `root:docker 660`.
- Secrets on disk: `/opt/cipheroom/.env` 600 root; `/etc/cipheroom` 700; TURN private key 600 root;
  `/etc/letsencrypt/{live,archive}` 700.
- Certificate renewal timer is scheduled. Swap 2 GB, swappiness 10.
- Outside scan (IPv4, TCP): open only 22 (operator IP), 443 (TURN/TLS), 7881 (LiveKit TCP); 7880, 2375/2376, 3000,
  3100, 3200, 4317, 8080, 8888, 9090, 9100 filtered.
- TLS on 443 presents a valid `turn-beta.alexfix.dev` certificate (expires 2027-01-09).
